# GimpanumMod

Мод для Minecraft **1.21.1** / **NeoForge 21.1.228**. Канон мира — в [LORE.md](LORE.md).

Задуман для боёв на физических конструкциях (sublevel'ах) из модов **Sable** и
**Create Aeronautics** и для отдельного измерения, вокруг которого эти бои идут.

## Что добавляет мод

- **Ядро** — креативный блок-цель, который оператор настраивает на месте (правой кнопкой,
  командами `/gimpanum core …` или в консоли `/gimpanum dashboard`): привязывает ники
  игроков и экипажи FTB Teams, задаёт команды и последствия гибели. При подтверждённом
  уничтожении Ядро роняет **Печать** — предмет со списком привязанных, — выполняет команды
  для каждого привязанного игрока и, если включено, взрывается. Переезд Ядра при сборке
  корабля уничтожением не считается.
- **Фонос-конвертеры** — неразрушимые обменники: принимают брошенные предметы и, набрав
  квоту, выдают другой. Найденные в мире берут предложения из настроек.
- **Измерение Гимпанум** — пустыня с лабиринтом пещер под ней, без воздуха, огня и роста
  растений, с пониженной тяжестью. Вход — через портальные арки.
- **Выбросы** — события на всё измерение раз в 10–40 минут.
- **Обитатели** — Ходоки и их Капитаны, Призраки кометы, Плазменные молнии, Поглотители.
- **Структуры** со Сгустками фоноса — наградами, спускающими ловушки.
- **Предметы высшего тира** — Крылья Радитажа, Биение Сердца Бога, Панцирь Склава,
  Огранка, Талисман лиловой королевы, Дар друидов.

Все числа, которые владелец сервера правит на ходу, лежат в `config/gimpanum/` и
перечитываются командой `/gimpanum config reload`. Образцы файлов — в джарке, в
`data/gimpanum/…/default_*.json`.

## Требования для сборки

- **JDK 21** (обязательно; NeoForge 21.1.x не запустится на 17)
- Gradle wrapper входит в репозиторий
- **Джарки модпака** в `other_mods_in_modpack/` (в git их нет): Sable, FTB Teams (с
  FTB Library и Architectury), Create Big Cannons (с Create и Ritchie's Projectile
  Library), JEI и Xaero's Minimap. Точные имена файлов — в `build.gradle`. В игре все эти
  моды необязательны, но классы-мосты к ним ссылаются на их типы напрямую, поэтому без
  джарок мод не компилируется; `compileJava` перечислит, каких файлов не хватает.

```bash
./gradlew build
```

## Ключевая архитектурная особенность

Sable-sublevel — это **не отдельный `Level`**. Блоки конструкции лежат в родительском
`ServerLevel`, в скрытом резервном регионе чанков («плот»), а видимое положение получается
трансформацией через `Pose3d`. Поэтому `blockEntity.getBlockPos()` у Ядра на конструкции — это
служебная координата, а не та точка, где игроки видят блок. Все эффекты (взрыв, дроп, позиция
для команд) обязаны считаться от **мировой** позиции:

```
world = pose.position() + pose.orientation() * ((local - pose.rotationPoint()) * pose.scale())
```

Sable в игре — **опциональная** зависимость: без неё мод работает, поддержка конструкций
отключается.

## Структура репозитория

- `other_mods_in_modpack/` — джарки модпака, используются как локальные dev-зависимости
  (не в git)
- `tools/` — скрипты на Python, которыми собраны шаблоны структур (`structures.py`)
