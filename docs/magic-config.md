# Настройки рунной магии

Три серверных файла в `config/gimpanum/magic/`:

| Файл | Что в нём | Читает ли песочница |
|---|---|---|
| `arcanes.json` | арканы: номера, поведения по ролям, частицы | да |
| `fields.json` | наборы арканных полей и катализаторы | да |
| `magic.json` | векторы рун, угол, шаг, цена, перезарядка, пределы | векторы, угол и шаг — да |

Если файла нет, при запуске сервера он копируется из образца в джарке
(`src/main/resources/data/gimpanum/magic/`).

## Перезагрузка и ошибки

- `/gimpanum magic reload` — перечитать три файла (уровень оператора 2, как у всей ветки `/gimpanum`).
- `/gimpanum config reload` перечитывает их тоже, вместе с остальными настройками мода.
- `/gimpanum magic` — сколько арканов и наборов прочитано.

Файлы читаются **вместе и строго**. Если хотя бы в одном есть ошибка, не применяется ничего:
действуют прежние настройки, а ошибки выводятся в чат (первые 15) и в журнал сервера (все).
Каждая ошибка — с путём до места, например:

```
arcanes.json.arcanes[1].order: ожидалось число, а здесь "много"
arcanes.json.arcanes[1].interfix[0].type: нет такого поведения «descnd»; есть: …
fields.json.sets.default.fields[0].arcane: аркана «lava» нет в arcanes.json
```

Неизвестное поле — тоже ошибка: почти всегда это опечатка в имени.

Если при **запуске** сервера файлы с ошибками, берётся встроенный образец, а ошибки пишутся в журнал.

Заклинание запоминает настройки в момент каста: перезагрузка посреди заклинания на него не действует.

## Отладка: `/gimpanum magic compile`

Разбирает заклинание без каста и печатает для каждой рунописи точку, аркан, номер и роль:

```
/gimpanum magic compile zhin.zhin.lun.gi.be gi dar.an
ЖИН·ЖИН·ЛУН·ГИ·БЭ → (2.7366, -1.3692, -0.3452) → fire [20] префикс
ГИ → (-1.0440, -0.3480, -0.4780) → heal [70] корень
ДАР·АН → (1.5521, 0.8139, -0.3220) → water [60] суффикс
```

Руны — латинскими id через точку, рунописи — через пробел. `compile_in <набор> <заклинание>` —
то же в другом наборе полей. Числа печатаются с четырьмя знаками — для сверки с песочницей.

## `magic.json`

```json
{
  "runes": { "an": [0.832, -0.042, 0.863], "be": [...], ... },
  "turnAngle": 55.0,
  "stepMultiplier": 1.0,
  "cost": { "foodPerRune": 1.0, "canKill": false, "healthPerFood": 1.0 },
  "cooldownSeconds": 3.0,
  "tabletUpgradeItem": "minecraft:netherite_ingot",
  "limits": {
    "blocksPerSpell": 256,
    "entitiesPerSpell": 16,
    "entityLifetimeSeconds": 120.0,
    "homingEntities": 32,
    "particlesPerTick": 600,
    "defaultTargetRadius": 16.0
  },
  "homing": { "searchIntervalTicks": 10, "searchRadius": 16.0 }
}
```

| Поле | Смысл |
|---|---|
| `runes` | вектор каждой из 12 рун. Ключи — id рун (см. ниже), нужны все 12 |
| `turnAngle` | угол поворота черепахи после шага, в градусах |
| `stepMultiplier` | множитель длины шага |
| `cost.foodPerRune` | цена каждой руны заклинания в единицах еды (1 = половинка окорочка) |
| `cost.canKill` | может ли цена убить. `false` — если заплатить можно только ценой жизни, каст не происходит |
| `cost.healthPerFood` | сколько здоровья (1 = половинка сердца) берётся за единицу еды, когда еда кончилась |
| `cooldownSeconds` | перезарядка магии игрока после любого каста |
| `tabletUpgradeItem` | предмет, который кладут в слоты улучшения таблички |
| `limits.blocksPerSpell` | сколько блоков одно заклинание (со всеми копиями) может изменить |
| `limits.entitiesPerSpell` | сколько сущностей-заклинаний (главная + копии) может породить одно заклинание |
| `limits.entityLifetimeSeconds` | жёсткий предел жизни сущности-заклинания |
| `limits.homingEntities` | сколько сущностей может одновременно наводиться на всём сервере; сверх предела `home` просто ждёт |
| `limits.particlesPerTick` | частиц магии на весь сервер за тик; сверх — не рисуются |
| `limits.defaultTargetRadius` | радиус поиска цели по умолчанию |
| `homing.searchIntervalTicks` | как часто наводящаяся сущность ищет цель заново |
| `homing.searchRadius` | радиус поиска цели при наведении |

Руны (порядок — это индекс, он стабилен):

| Индекс | Руна | id |
|---|---|---|
| 0 | АН | `an` |
| 1 | БЭ | `be` |
| 2 | ВОЛ | `vol` |
| 3 | ГИ | `gi` |
| 4 | ДАР | `dar` |
| 5 | ЭР | `er` |
| 6 | ЖИН | `zhin` |
| 7 | ЗАР | `zar` |
| 8 | ИМ | `im` |
| 9 | КОЛ | `kol` |
| 10 | ЛУН | `lun` |
| 11 | МАР | `mar` |

## `fields.json`

```json
{
  "sets": {
    "default": {
      "catalysts": ["gimpanum:crystal_shard"],
      "fields": [
        {"arcane": "fire", "center": [4.72, -1.16, -0.87], "radius": 1.05}
      ]
    },
    "scalk":   {"catalysts": ["minecraft:sculk"], "turnAngle": 55.0, "stepMultiplier": 1.0, "fields": []},
    "citrine": {"catalysts": [], "fields": []}
  }
}
```

- `sets` — именованные наборы. Набор `default` обязателен и не может быть пустым.
- `catalysts` — id предметов, которые выбирают этот набор, когда лежат во второй руке. Один предмет — не больше
  чем в одном наборе. Поле необязательное.
- `turnAngle`, `stepMultiplier` — необязательные, переопределяют значения из `magic.json` для этого набора.
- `fields` — поля набора, **порядок значим** (см. правила ниже).

Какой набор используется:

1. Во второй руке (той, где нет таблички) ничего нет — `default`.
2. Предмет привязан к набору, и набор не пуст — этот набор.
3. Предмет ни к чему не привязан **или привязан к пустому набору** — `default`.

Пункт 3 для пустого набора — допущение реализации: пустой набор не может дать аркан, а рунописи без
аркана не бывает. Сейчас `scalk` и `citrine` пусты, поэтому скалк во второй руке работает как без катализатора.

## `arcanes.json`

```json
{
  "arcanes": [
    {
      "id": "fire",
      "name": "Огонь",
      "order": 20,
      "root":     [{"type": "damage", "amount": 2.0}, {"type": "ignite", "seconds": 3.0}],
      "prefix":   [{"type": "extend_duration", "factor": 2.0}],
      "suffix":   [{"type": "echo_root", "interval": 1.0, "duration": 3.0}],
      "interfix": [{"type": "wait", "seconds": 4.0}],
      "particles": { "root": {...}, "prefix": {...}, "suffix": {...}, "interfix": {...} }
    }
  ]
}
```

| Поле | Смысл |
|---|---|
| `id` | латиница в нижнем регистре, цифры, `_`; уникален |
| `name` | название для людей |
| `order` | порядковый номер, целое **больше нуля**. Уникальность не требуется |
| `root`, `prefix`, `suffix`, `interfix` | списки поведений для каждой роли. Любой можно опустить — пустая роль |
| `particles` | частицы по ролям, необязательно (см. ниже) |

Поведение — объект с полем `type` и параметрами. Все параметры обязательны, кроме отмеченных.

## Библиотека поведений

Поведения трёх видов:

- **изменения контекста** — выбирают цели, задают форму, множат параметры. Роли: корень, префикс, суффикс;
- **действия** — делают что-то с целями или блоками. Роли: корень, префикс, суффикс;
- **процессы** — растянуты во времени. Только интерфикс, и в интерфиксе только они.

### Изменения контекста

| `type` | Параметры | Что делает |
|---|---|---|
| `extend_duration` | `factor` (0…100) | длительные эффекты **корня** длятся в `factor` раз дольше |
| `periodic_if_instant` | `interval`, `duration` (с) | если корень мгновенный (ни одного длительного действия), он повторяется: в момент применения и затем каждые `interval` с, пока от начала прошло меньше `duration` с. При 3/9 — три раза: 0, 3, 6 с |
| `amplify` | `percent` (−100…10000) | основной параметр корня больше на `percent` % |
| `target_look` | `range` (0…32) | цель — живая сущность под прицелом не дальше `range`; луч обрывается о стену |
| `target_radius` | `radius` (0…32), `includeCaster` | цели — все живые в радиусе `radius` |
| `shape_cone` | `angle` (полный раствор, 0…180°), `length` (0…32) | форма — конус по взгляду кастера в момент каста |
| `shape_sphere` | `radius` (0…32) | форма — шар |

### Действия

| `type` | Параметры | Основной параметр | Длительное | Что делает |
|---|---|---|---|---|
| `damage` | `amount` | `amount` | нет | магический урон |
| `ignite` | `seconds` | — | да | поджечь |
| `heal` | `amount` | `amount` | нет | вылечить |
| `effect` | `effect` (id эффекта), `seconds`, `amplifier` (необяз., 0) | — | да | наложить эффект |
| `cleanse` | — | — | нет | снять все эффекты и потушить — кроме эффектов и горения, наложенных **этим же** заклинанием |
| `echo_root` | `interval`, `duration` (с) | — | нет | на месте сущности-заклинания появляется копия, которая каждые `interval` с, пока прошло меньше `duration`, применяет **только корень** — без префиксов и суффиксов, с целью по умолчанию от копии |
| `water` | `seconds` (−1 — навсегда) | — | если `seconds` > 0 | воздух → источник воды, блоки с `waterlogged` — обводняются. Там, где вода испаряется (Незер), испаряется с шипением |
| `light` | `level` (0…15), `seconds` (−1 — навсегда) | `level` | если `seconds` > 0 | невидимый блок света `minecraft:light`, только в воздухе |

Множители `extend_duration` и `amplify` действуют **только на действия корня**. Действия в роли
префикса или суффикса (например, свечение `effect` в суффиксе света) не продлеваются и не усиливаются.

### Процессы интерфикса

| `type` | Параметры | Что делает |
|---|---|---|
| `wait` | `seconds` | ждать |
| `descend` | `maxDistance` (0…256), `speed` (блоков за тик) | опустить сущность-заклинание до верха ближайшего твёрдого блока под ней, не дальше `maxDistance` |
| `home` | `seconds`, `speed` (блоков за тик), `excludeCaster` | `seconds` с двигаться к ближайшей живой сущности. Поиск — раз в `homing.searchIntervalTicks` тиков в радиусе `homing.searchRadius` |
| `emit_light` | `level` (0…15) | пока идёт интерфикс, в позиции сущности стоит временный блок света; переезжает вместе с ней, убирается в конце. Интерфикс не удлиняет |

Процессы одного интерфикса идут **одновременно**. Интерфикс кончается, когда кончились все
блокирующие (все, кроме `emit_light`). Интерфикс только из `emit_light` не ждёт ничего.

## Как исполняется заклинание

1. ПКМ табличкой. Сервер читает табличку, проверяет перезарядку, разбирает заклинание и списывает цену.
2. В позиции **глаз** кастера появляется невидимая сущность-заклинание. Она хранит программу,
   кастера и направление взгляда в момент каста.
3. Сущность исполняет корни по очереди. Для каждого корня:
   1. изменения контекста: префиксы слева направо, затем суффиксы слева направо, затем сам корень;
   2. действия префиксов, затем корня, затем суффиксов.
4. Между корнями — интерфикс, если он есть. Без интерфикса следующий корень исполняется в тот же тик.
5. Сущность исчезает, когда исполнены все корни и закончились её фоновые повторы
   (периодический корень). Копии от `echo_root` — отдельные сущности со своим сроком.

Сущность-заклинание не сохраняется на диск: после перезапуска сервера заклинание не продолжается.
Временные блоки (свет, вода со сроком) записаны отдельно и убираются и после перезапуска — только если
блок всё ещё тот, что ставило заклинание. Время — игровое.

### Как комбинируются префиксы выбора

Выбор целей — **цепочка**. В начале набор «якорей» — одна точка, сама сущность-заклинание.
Каждый шаг выбора превращает **каждый** якорь в новые и объединяет результат:

- `target_look`: от якоря-сущности луч идёт от её глаз; от начальной точки — от глаз кастера.
  Направление — всегда взгляд кастера в момент каста;
- `target_radius`: все живые вокруг якоря.

Значит, «взгляд, затем радиус 2» — все вокруг того, на кого смотришь; «радиус, затем взгляд» — те, на кого
«смотрят» стоящие рядом (в направлении взгляда кастера).

**Пустой результат шага откатывается**: набор остаётся прежним, как будто шага не было.

Форма (`shape_cone`, `shape_sphere`) — тоже шаг цепочки, но её результат — **область**: блоки и живые
внутри неё. Блок внутри, если внутри его центр. Форма не откатывается, даже если живых в ней нет:
огненный конус в пустоту не должен вместо этого поджечь кастера. Вершина конуса — глаза якоря-сущности
или сама точка-якорь.

**Цель по умолчанию**: если ни один шаг не выбирал цели, действия бьют ближайшую к сущности-заклинанию
живую сущность в радиусе `limits.defaultTargetRadius`. Обычно это сам кастер.

**Блоки** для `water` и `light`: выделенные формой; без формы — блок, в котором стоит каждая цель;
без целей — блок самой сущности-заклинания.

Защита территорий: перед изменением блока заклинание шлёт событие установки блока от имени кастера
(`BlockEvent.EntityPlaceEvent`) и проверяет ванильные запреты (защита спавна, граница мира, режим
приключения). Если в сборке стоит мод приватов, который слушает это событие, на чужой земле блок не встанет.

## Частицы

```json
"particles": {
  "root":     {"particle": {"type": "minecraft:flame"}, "count": 24, "spread": 0.35, "speed": 0.03},
  "prefix":   {"particle": {"type": "minecraft:dust", "color": [1.0, 0.45, 0.05], "scale": 1.0}, "count": 1},
  "suffix":   {"particle": {"type": "minecraft:small_flame"}, "count": 1, "spread": 0.03},
  "interfix": {"particle": {"type": "minecraft:dust_color_transition", "from_color": [0.3, 1.0, 0.4], "to_color": [1, 1, 1], "scale": 1.0}, "count": 2}
}
```

`particle` — описание частицы в ванильном формате (тот же, что у команды `/particle` в JSON-виде),
разбирается ванильным кодеком: доступны все частицы игры с их параметрами. Примеры:
`{"type": "minecraft:flame"}`, `{"type": "minecraft:dust", "color": [r, g, b], "scale": s}`,
`{"type": "minecraft:dust_color_transition", "from_color": [...], "to_color": [...], "scale": s}`,
`{"type": "minecraft:block", "block_state": {"Name": "minecraft:stone"}}`.

`count` (1…1000, по умолчанию 1) — частиц в одной точке узора, `spread` (0…16, по умолчанию 0) — разброс,
`speed` (0…10, по умолчанию 0) — скорость.

Узор задаёт **роль**, аркан выбирает только частицы:

| Роль | Узор |
|---|---|
| корень | вспышка на каждой цели; без целей — над блоками действия (не больше 24 точек) |
| префикс | обводка того, что он выбрал: луч до цели (`target_look`), сфера (`target_radius`, `shape_sphere`), контур конуса (`shape_cone`); без формы — кольцо вокруг сущности-заклинания |
| суффикс | спираль вокруг каждой цели |
| интерфикс | след: каждый тик в позиции сущности-заклинания |

Обводки рисуются с плотностью 3 точки на блок; каждая точка — `count` частиц.

## Математика (для песочницы)

Всё в `double`. Реализация — `src/main/java/com/kirbornu/gimpanum/magic/core/`, тесты — в `src/test/`.

### Рунопись → точка

Кватернион `[w, x, y, z]`, произведение Гамильтона. `rotate(q, v) = (q ⊗ (0, v) ⊗ q*).xyz`.
`axisAngle(u, θ) = [cos(θ/2), û·sin(θ/2)]`; для нулевого вектора — единичный кватернион.

```
p = (0, 0, 0); q = [1, 0, 0, 0]
для каждой руны i слева направо:
    p = p + rotate(q, V[i] * stepMultiplier)
    q = q ⊗ axisAngle(V[i], turnAngle)
```

### Точка → аркан

1. Внутри поля: `distance(p, center) <= radius`.
2. Внутри одного или нескольких — побеждает меньший радиус; при равных — ближайший центр; при полном
   равенстве — раньше в списке.
3. Вне всех — ближайший центр; при равенстве — раньше в списке.

### Роли

Номера `order` с нулями по краям. Каждый аркан сравнивает свой номер с левым (L) и правым (R) соседом:

| | R < | R = | R > |
|---|---|---|---|
| **L <** | корень | корень | префикс |
| **L =** | корень | интерфикс | префикс |
| **L >** | суффикс | суффикс | интерфикс |

Схлопывание: из нескольких корней подряд работает первый, из нескольких интерфиксов подряд — первый.
Префикс — к ближайшему корню справа, суффикс — к ближайшему слева. Между двумя корнями всегда
идут: суффиксы, не больше одного интерфикса, префиксы — в этом порядке (проверено тестом на 20 000
случайных заклинаний).

### Чтение таблички

Видимая часть сетки читается построчно, слева направо, сверху вниз. Пустая ячейка — пробел; несколько
подряд — один пробел; пустые в начале и в конце не значат ничего. **Конец строки пробелом не считается**:
рунопись продолжается на следующей строке. Это буквальное прочтение постановки («построчно» как один
поток ячеек); если нужно иначе — меняется в `TabletText.read`.

## Табличка

- Shift+ПКМ — открыть сетку, ПКМ — сотворить.
- Базовая сетка 2×2. Слот «Ряды» добавляет строку на каждый предмет улучшения, слот «Столбцы» — столбец,
  до 5 штук в каждом (7×7).
- Если вынуть улучшение, глифы из исчезнувших ячеек уходят в инвентарь, а что не влезло — выпадает.
- Глифы хранятся на полной сетке 7×7 по строкам, поэтому при добавлении столбца не переезжают.
- Глифы при касте не расходуются.
- Перезарядка — у игрока (вложение `gimpanum:magic_cooldown`), а не у таблички. Ванильная полоска
  перезарядки на табличках — только для вида; из-за неё же во время перезарядки табличку нельзя и открыть
  (игра не вызывает предмет на перезарядке вовсе).
- Цена — точка расширения `SpellPayment`: сейчас `FoodPayment`, потом можно подставить эрозию и хрусталь.
